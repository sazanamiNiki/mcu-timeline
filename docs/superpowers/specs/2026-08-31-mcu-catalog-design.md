# MCU作品カタログサイト 設計書

作成日は2026年8月31日である。同日に3ビュー構成へ改訂した。状態は改訂版で、ユーザーの確認を待っている。

## 1. 目的

マーベル・スタジオのMCU作品を一覧表示する静的サイトを作る。GitHub Pagesで公開し、初心者とファンの両方が使う。初心者は観る順番と依存関係を調べ、ファンは公開日や新作の情報を確認する。

## 2. 収録範囲

収録するのは、MCU正史の実写作品だけである。劇場映画43件（公開予定5件を含む）と、Disney+の実写ドラマ・スペシャル20件が対象になる。ドラマはシーズン単位で1件と数える。

次の作品は収録しない。

- アニメ作品（『ホワット・イフ...?』『アイ・アム・グルート』『アイズ・オブ・ワカンダ』『マーベル・ゾンビーズ』など）
- 『X-MEN '97』（MCU外）
- 旧マーベル・テレビジョン作品（『エージェント・オブ・シールド』、Netflix版『デアデビル』など）

収録の判定は `data/mcu-works.json` のフィールドで行う。`films` は全件を対象にする。`series` は `canon` が `main` で、`type` が `series` か `special` のものを対象にする。

## 3. 画面構成

サイトは1ページ（`index.html`）で、上部のタブで4つのビューを切り替える。

| タブ | 内容 |
|------|------|
| 公開順 | 米国公開日順の横タイムライン |
| 時系列 | 作中の年代順の横タイムライン |
| 依存関係図 | 63作品の「先に観る」関係のSVG |
| ガイド | 短縮ルートと予習マップ |

ヘッダーにはサイト名・検索ボックス・タブを置く。フッターにはTMDBのクレジット表記と、データの更新日を置く。

開いているタブはURLのハッシュに持たせる。`#release` `#story` `#graph` `#guide` の4つで、リンクから直接そのタブを開ける。

## 4. 作品カード

カードには次の項目を出す。

- ポスター画像（TMDB）
- 邦題（ドラマはシーズン番号つき）
- 原題（小さく表示）
- 種別（映画／ドラマ／スペシャル）とフェーズ
- 日本公開日と米国公開日
- 1行あらすじ（40字程度）
- 視聴済みのチェック
- 公開予定の印（未公開作のみ）

興収・評価スコア・監督・上映時間・話数は出さない。

## 5. タイムライン（公開順・時系列）

2つのタイムラインは同じ部品で描く。横スクロールで、左が古く右が新しい。カードは等間隔に並べ、日付の間隔には比例させない。

公開順タブは、年ごとの見出しとフェーズの色帯を上に置く。時系列タブは `timeline_order` の順に並べ、作中の年代 `story_year` を見出しに使う。

操作は3つある。

- 並べ替え: 「古い順」と「新しい順」で左右を反転する
- 主要作ハイライト: 切り替えると主要作以外のカードを薄く表示する
- 検索: 一致しないカードを隠す

スマホでは横スクロールで操作し、カードは縮小する。

## 6. 依存関係図

依存関係図は自前のSVGで描く。外部ライブラリは使わない。

配置は2軸で決める。横軸は公開順で、縦軸は系列レーンにする。レーンは次の12本を用意する。

- アベンジャーズ
- アイアンマン系
- キャプテン・アメリカ系
- ソー系
- ガーディアンズ系
- スパイダーマン系
- ストレンジ／ワンダ系
- キャプテン・マーベル系
- ストリート系
- アントマン系
- ブラックパンサー系
- その他

ノードはポスターの小さなサムネイルと略称で表す。視聴済みの作品は、ノードの角に緑の印で示す。辺は「先に観る作品」から「後に観る作品」へ向かう曲線にする。

操作は次のとおりにする。

- ドラッグで移動する。拡大縮小はボタンと2本指のピンチで行い、ホイール単体では反応しない
- ノードを押すと、概要（邦題・原題・種別・公開日・あらすじ）をパネルに出す
- あわせて前提作品（祖先）を強調し、他を薄くする
- 公開予定作を押した状態が、予習リストの図での表現にあたる
- 検索に一致したノードを強調する

辺のデータは `data/dependencies.json` に置く。私が草案を作り、ユーザーが調整して確定する。

## 7. ガイド

ガイドタブには次の3つを置く。リストに行番号は付けない。

| 項目 | 形式 | 元データ |
|------|------|---------|
| 短縮ルート | リスト（番号なし） | `essential` フラグ |
| 予習リスト | リスト（番号なし） | `data/guides.json` |
| 予習マップ | archify の小図 | `diagrams/*.html` |

リストの各行は縮小カードと視聴済みの印を持つ。予習リストと予習マップは『ヴィジョンクエスト』と『アベンジャーズ／ドゥームズデイ』の2件を用意する。公開順で全部観るルートは、公開順タブが兼ねる。

短縮ルートの作品は、私が一般的な鑑賞ガイドを参考に草案を作る。ユーザーがその草案を調整して確定する。時系列順は、Marvel公式が示す時系列（Disney+の「タイムライン順」）を出典にする。

## 8. 検索と視聴済み

検索ボックスの入力に応じて、邦題と原題の部分一致で作品を選ぶ。大文字と小文字は区別しない。選ばれた作品の扱いは、タイムラインでは表示、依存関係図では強調になる。

カードのチェックを押すと、視聴済みの状態を切り替える。ガイドの一覧では、カード全体のタップでも切り替えられる。状態は localStorage のキー `mcu-watched` に、作品 id の配列として保存する。

保存はブラウザ単位で、別の端末やブラウザには引き継がれない。読み書きは try/catch で囲む。localStorage が使えない環境では、印なしで表示する。

## 9. データ設計

作品データは既存の `data/mcu-works.json` を使う。収録対象のレコードに、次のフィールドを追加する。

| フィールド | 型 | 内容 |
|-----------|-----|------|
| `tmdb_id` | 数値 | TMDBの作品ID |
| `poster_path` | 文字列 | TMDBのポスターのパス |
| `timeline_order` | 数値 | 作中の時系列順の番号 |
| `story_year` | 文字列 | 作中の年代の表示用 |
| `essential` | 真偽値 | 短縮ルートに含めるか |
| `lane` | 文字列 | 依存関係図のレーン |

依存関係は `data/dependencies.json` に置く。各要素は `from`、`to`、`note` を持つ。`from` は先に観る作品、`to` は後に観る作品、`note` は理由の一言を表す。

予習リストは `data/guides.json` に置く。各要素は対象作品の id と、前提作品の id と理由の配列を持つ。

あらすじは既存の `summary_ja` を使う。長い文は40字程度に整える。

## 10. ポスター取得

ポスターは `scripts/fetch_posters.py` で取得する。Python 3の標準ライブラリだけで書き、追加のインストールを不要にする。

スクリプトは環境変数 `TMDB_API_KEY` を読む。映画は `search/movie` に原題と公開年を渡し、ドラマは `search/tv` に原題を渡して `tmdb_id` を解決する。言語は `ja-JP` を優先し、日本語のポスターがなければ英語にする。

解決できなかった作品は一覧で表示する。その作品は手作業で `tmdb_id` を入れ、再実行する。

ページ側は `https://image.tmdb.org/t/p/w342` にパスをつなげて画像を表示する。この表示にAPIキーは要らない。`poster_path` がない作品には、タイトル入りのプレースホルダーを出す。

## 11. archify の小図

予習マップは archify（MIT）で生成する。入力は `diagrams/src/*.architecture.json`、出力は `diagrams/*.html` に置く。生成物はリポジトリにコミットし、公開ページは生成物だけを読む。

archify は `npx skills add tt-a1i/archify -g` で `~/.claude/skills/archify` に入れる。生成コマンドは `node ~/.claude/skills/archify/bin/archify.mjs deliver architecture <入力> <出力> --quality standard` である。

検証で分かった制約を守る。

- ノードは12個以下にする。63作品の全体図には使えない
- ラベルは略称にし、ノード幅より短くする
- 辺は `fromSide: bottom` と `toSide: top` で扇状に集める
- 凡例は `meta.legend` で「映画」「ドラマ」に上書きする
- 品質は `standard` にする（`showcase` は文字サイズ判定で通らない）

## 12. 技術構成

フレームワークとビルド工程は使わない。JavaScriptはESモジュールで分ける。

| ファイル | 役割 |
|---------|------|
| `index.html` | ページ本体とタブ |
| `assets/style.css` | 共通スタイル |
| `assets/common.js` | 共通処理（読込・保存・描画） |
| `assets/timeline.js` | 2つのタイムライン |
| `assets/graph.js` | 依存関係図のSVG |
| `assets/guide.js` | ガイドタブ |
| `assets/app.js` | タブ切り替えと検索 |
| `data/mcu-works.json` | 作品データ |
| `data/dependencies.json` | 依存関係 |
| `data/guides.json` | 予習リスト |
| `diagrams/` | archify の入力と出力 |
| `scripts/fetch_posters.py` | ポスター取得 |
| `scripts/check_data.py` | データ整合性の検査 |

ローカルでの確認は `python3 -m http.server 8000` で行う。GitHub Pagesはリポジトリのルートから配信する。

## 13. デザイン

ダーク基調にする。色はCSS変数で定義し、差し色は1色に絞る。差し色は不透明度0.8に抑えて、強すぎない赤にする。

件数・行番号・ズーム率のような装飾的な数字は画面に出さない。公開日などのデータの数値だけを表示する。

視聴済みのカードは、上端の色帯だけを緑で示す。フェーズの色帯は差し色の明度を変えて区別する。

ポスターは縦横比2:3にする。画像には `loading="lazy"` をつける。

## 14. エラー処理

- JSONの読み込みに失敗したら、本文にメッセージを出す
- ポスターの読み込みに失敗したら、`onerror` でプレースホルダーに置き換える
- localStorage が使えなければ、チェックを無効にして印なしで表示する
- 依存関係に循環があれば、`check_data.py` が検出して止める

## 15. 確認方法

`scripts/check_data.py` で次を検査する。必須フィールドの有無、id の重複、`dependencies.json` と `guides.json` の id が作品データに存在するか、依存関係に循環がないか、である。

ブラウザでは次を手動で確認する。

- 4つのタブが切り替わり、URLのハッシュと連動する
- 検索でタイムラインのカードが絞られ、依存関係図のノードが強調される
- 並べ替えでタイムラインの左右が反転する
- 主要作ハイライトで主要作以外が薄くなる
- 依存関係図でノードを押すと概要が出て、祖先が強調される
- 視聴済みが再読み込み後も残る
- 予習マップの iframe が表示される
- スマホ幅（375px）で横スクロールできる

## 16. 公開手順

1. `git init` し、GitHubにリポジトリを作る（名前は未定）
2. `main` ブランチをpushする
3. Settings → Pages で `main` のルートを配信元にする
4. TMDBの利用規約に従い、フッターのクレジット表記を確認する

## 17. スコープ外

次の項目は今回作らない。

- 評価・メモ・ウォッチリスト
- 視聴済みのエクスポートとインポート
- 日英の切り替え
- 興収・評価スコア・監督・上映時間の表示
- 63作品の全体図を archify で作ること
